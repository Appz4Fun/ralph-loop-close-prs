## 2026-06-03 - Parallelize N+1 GH CLI Operations
**Learning:** Sequential calls to the GitHub CLI (`gh`), specifically within `_filter_to_still_open_prs` where `_pr_is_still_open` calls `gh pr view`, act as a significant performance bottleneck due to process instantiation overhead and network latency. Because multiple PRs may need to be filtered consecutively, an N+1 query problem occurs at the subprocess level.
**Action:** When filtering or fetching state for multiple items using external CLI commands like `gh`, execute the commands concurrently using `concurrent.futures.ThreadPoolExecutor` with a reasonable worker limit (e.g., `min(10, N)`). Use `executor.map` to preserve original evaluation order and catch/wrap exceptions in a helper function so that transient/network errors can be logged or handled predictably without breaking the entire sequence.
