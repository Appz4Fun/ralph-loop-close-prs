## 2024-05-24 - N+1 Sequential Execution Bottleneck in `gh` CLI Calls
**Learning:** Subprocess calls to the GitHub CLI ('gh') via `_pr_is_still_open` within a sequential loop over multiple PRs create a significant N+1 performance bottleneck. Even checking states for a modest number of PRs can block the supervisor for seconds or minutes because of the serial execution of `subprocess.run()`.
**Action:** Use `concurrent.futures.ThreadPoolExecutor` to execute multiple `gh` CLI subprocess calls concurrently when checking PR states. Ensure that the original order is preserved using `executor.map`, and correctly handle empty lists by guarding the creation of the thread pool to avoid `ValueError` for `max_workers=0`. Capture exceptions in a wrapper function to maintain error-handling parity with the sequential version.
