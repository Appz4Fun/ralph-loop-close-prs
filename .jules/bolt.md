## 2024-05-18 - Batch concurrent PR state checking
**Learning:** Subprocess calls to the GitHub CLI ('gh'), typically executed via '_gh_json' or '_gh_run_with_retry', are a significant performance bottleneck. When checking states for multiple PRs, using concurrency (`concurrent.futures.ThreadPoolExecutor`) avoids N+1 sequential execution delays.
**Action:** Ensure that the original order is preserved by using `executor.map`, and capture exceptions (like `CommandError`) in a helper wrapper so they can be yielded and handled gracefully in order. Always add a guard clause (e.g., `if not items: return []`) to prevent a `ValueError` caused by `max_workers=0` when the collection is empty.
