## 2026-06-24 - Speed up gh cli process bottlenecks with ThreadPoolExecutor
**Learning:** Checking the state of open PRs using `_pr_is_still_open` inside `_filter_to_still_open_prs` happens in a serial loop. `_pr_is_still_open` delegates to `gh pr view` which has significant performance overhead due to spawning subprocesses and making API calls.
**Action:** When filtering a list of items calling a high-latency system function or external API like `gh`, use `concurrent.futures.ThreadPoolExecutor` with `executor.map` to parallelize work while preserving response order and handling exceptions explicitly. Note that when the list might be empty, adding a guard clause like `if not items: return []` is required to prevent a `ValueError` caused by `max_workers=0` in `ThreadPoolExecutor`.
