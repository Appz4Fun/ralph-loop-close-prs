## 2025-02-20 - Subprocess Bottlenecks with GitHub CLI
**Learning:** Subprocess calls to the GitHub CLI (`gh`), typically executed via `_gh_json` or `_gh_run_with_retry`, are a significant performance bottleneck. When checking states for multiple PRs sequentially (N+1 delays), it severely degrades performance.
**Action:** When checking states for multiple PRs, use concurrency (e.g., `concurrent.futures.ThreadPoolExecutor`) to avoid N+1 sequential execution delays. Ensure that the original order is preserved by using `executor.map`, and capture exceptions (like `CommandError`) in a helper wrapper so they can be yielded and handled gracefully in order.
